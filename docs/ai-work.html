The problem

Good portfolio claims need evidence.

A metric can be real yet still be framed too broadly. Before updating a public ML portfolio, I needed a small check that compares proposed wording with the approved case-study record and flags claims that are unsupported, sensitive, or larger than the prototype’s actual scope.

Intended outcome

Make portfolio updates easier to review without delegating publication authority to an AI system.

The final decision to change or publish anything stays with a person.

What I built

A deployed, responsive portfolio that presents a public-safe content-prioritisation case study, its evaluation result, its evidence links, and its limits.

How the personal agent works

One narrow, repeatable review workflow

  1. Receive a candidate sentence or short paragraph for a public ML portfolio.
  2. Stop obvious secrets, client-identifying wording, and broad workflow claims locally.
  3. Read only the approved public-safe case-study context and current public home-page source.
  4. Make one read-only reachability check to the live portfolio.
  5. Return a structured evidence decision and save a local audit record for human review.

Tools and knowledge used

The implementation combines Python guardrails, a structured gpt-5-mini review step, an approved Markdown evidence packet, the current public site source, and one fixed HTTPS reachability check.

It has no deployment, publishing, email, posting, booking, or write authority.

Safety and limitations

What the agent does not do

It does not access datasets, client information, credentials, private notebooks, raw queries, or other secrets. It does not edit the website or publish a result.

What its output means

An ALLOW is advisory, not permission to publish. The agent cannot validate new metrics, jobs, production status, or business outcomes outside its intentionally narrow evidence packet.
