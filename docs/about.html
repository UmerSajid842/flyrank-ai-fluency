About

Machine-learning work that can be inspected.

I am building entry-level ML case studies that make a decision problem, evaluation, and limitation visible rather than hiding them behind generic AI claims.

Working principle

Start with a narrow, real decision. Explain the method in public-safe terms. Show the reported result. Name the boundary. Link the evidence.

Current focus

Leakage-aware evaluation for a content-prioritisation prototype, plus the documentation and presentation work needed to make the result understandable.

Tooling in context

Tools support the evidence; they are not the headline.

The public project uses Python-based data analysis and machine-learning work documented in the linked repository. I list tools only after the problem, result, and limitations so that a reader can understand what the work is for before inspecting implementation details.
